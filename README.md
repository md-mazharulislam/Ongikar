# অঙ্গীকার (Ongikar)

> পুনর্ব্যবহারযোগ্য উপকরণ বিনিময়, ডিজিটাল ওয়ালেট ও কমিউনিটি ব্যবস্থাপনার জন্য একটি সম্পূর্ণ ফুল-স্ট্যাক ওয়েব অ্যাপ্লিকেশন।
>
> মানুষ তাদের সংগ্রহ করা তামাকজাত বর্জ্য (সিগারেটের কাগজ, তামাক, তুলা, তুলার পুতুল) জমা দিয়ে সরাসরি নগদ মূল্য পান — এবং একই প্ল্যাটফর্মে একটি সম্পূর্ণ ডিজিটাল ওয়ালেট ব্যবহার করে টাকা পাঠাতে, জমাতে, দান করতে ও সঞ্চয় করতে পারেন।

এই ডকুমেন্টটি প্রজেক্টের সবকিছু ব্যাখ্যা করে — এটি কী করে, কীভাবে তৈরি, কীভাবে চালাতে হয়, এবং সমস্যা হলে কী করতে হয় — যাতে কোনো প্রযুক্তিগত পটভূমি না থাকলেও যে কেউ এটি বুঝে চালাতে পারেন।

## ১. এই প্রজেক্টটি কী

**অঙ্গীকার** একটি কমিউনিটি-চালিত প্ল্যাটফর্ম যার দুটি প্রধান অংশ:

1. **উপকরণ বিনিময় (Exchange Program):** ব্যবহারকারীরা সিগারেটের কাগজ, তামাক, তুলা ও তুলাজাত পণ্যের মতো পুনর্ব্যবহারযোগ্য উপকরণ জমা দিয়ে সরাসরি তাদের ডিজিটাল ওয়ালেটে নগদ মূল্য পান। এটি পরিবেশ দূষণ ও তামাকজাত বর্জ্য হ্রাসে উৎসাহ দেয়।
2. **ডিজিটাল ওয়ালেট:** প্রতিটি ব্যবহারকারীর একটি ওয়ালেট থাকে যেখানে তারা টাকা যোগ করতে, অন্য ব্যবহারকারীকে পাঠাতে, উত্তোলন করতে, বিল পরিশোধ করতে, দান করতে, সঞ্চয়/ডিপিএস করতে, বিনিয়োগ করতে এবং রিওয়ার্ড পয়েন্ট অর্জন ও রিডিম করতে পারেন।

এছাড়াও রয়েছে:
- **ম্যানেজমেন্ট/ফাউন্ডার টিম পেজ** — কারা এই প্রতিষ্ঠান চালাচ্ছেন তার পরিচিতি
- **অ্যাডমিন প্যানেল** — পুরো প্ল্যাটফর্ম নিয়ন্ত্রণ করার জন্য একটি আলাদা ড্যাশবোর্ড

পুরো অ্যাপ্লিকেশনটি **বাংলা ভাষায়** ডিজাইন করা — UI টেক্সট, এরর মেসেজ, সবকিছু বাংলায়, উপযুক্ত বাংলা ফন্ট ব্যবহার করে (Hind Siliguri / Baloo Da 2), এবং **সম্পূর্ণ রেসপন্সিভ** (মোবাইল, ট্যাবলেট, ডেস্কটপ সব ডিভাইসে ভালোভাবে কাজ করে)।

## ২. ব্যবহৃত প্রযুক্তি (Tech Stack)

| স্তর | প্রযুক্তি |
|---|---|
| Frontend | React 19 (Vite), React Router v7, Axios |
| Backend | Node.js, Express.js |
| Database | MongoDB (Mongoose ODM) |
| Authentication | JWT (JSON Web Token), bcryptjs (পাসওয়ার্ড হ্যাশিং) |
| Styling | প্লেইন CSS (কাস্টম ডিজাইন সিস্টেম, কোনো ফ্রেমওয়ার্ক নেই) |

| Containerization | Docker + Docker Compose |
| Database Admin UI | Mongo Express |
| ফন্ট | Google Fonts: Hind Siliguri (বডি টেক্সট), Baloo Da 2 (হেডিং) |
| আইকন | Font Awesome 6 |

## ৪. সিস্টেম কীভাবে কাজ করে (Architecture)

```
                        ┌─────────────────────────┐
   ব্যবহারকারীর ব্রাউজার  ─────▶  │   Nginx (frontend)      │
                        │   • React স্ট্যাটিক ফাইল  │
                        │     সার্ভ করে             │
                        │   • /api/* রিকোয়েস্ট      │
                        │     backend-এ প্রক্সি করে │
                        └───────────┬─────────────┘
                                    │
                                    ▼
                        ┌─────────────────────────┐
                        │  Express.js (backend)    │
                        │  • JWT দিয়ে অথেন্টিকেশন   │
                        │  • সব বিজনেস লজিক        │
                        │  • ওয়ালেট/ট্রানজ্যাকশন    │
                        └───────────┬─────────────┘
                                    │  Mongoose
                                    ▼
                        ┌─────────────────────────┐
                        │      MongoDB             │
                        │  Users, Wallets,          │
                        │  Transactions, Items,     │
                        │  TeamMembers,             │
                        │  PaymentMethods           │
                        └─────────────────────────┘
```

**কেন Nginx-এ প্রক্সি করা হয়?** ব্রাউজার শুধু একটি origin-এর সাথে কথা বলে (frontend-এর ঠিকানা), backend-এর সরাসরি হোস্ট/পোর্ট জানার দরকার নেই। এতে CORS (Cross-Origin) সমস্যা সম্পূর্ণ এড়ানো যায় এবং প্রোডাকশনে ডিপ্লয় করাও সহজ হয়।

**অথেন্টিকেশন ফ্লো:** লগইন/সাইনআপে সফল হলে সার্ভার একটি JWT টোকেন দেয়, যা ব্রাউজারের `localStorage`-এ সংরক্ষিত হয়। প্রতিটি পরবর্তী API রিকোয়েস্টে এই টোকেন `Authorization: Bearer <token>` হেডারে পাঠানো হয় (এটি `frontend/src/api/axios.js`-এ স্বয়ংক্রিয়ভাবে হয়)। ব্যাকএন্ডের `middleware/auth.js` প্রতিটি প্রোটেক্টেড রুটে এই টোকেন যাচাই করে।

## ৫. বৈশিষ্ট্যসমূহ বিস্তারিত

### অথেন্টিকেশন
- ফোন নম্বর + পাসওয়ার্ড দিয়ে সাইনআপ/লগইন
- পাসওয়ার্ড bcrypt দিয়ে হ্যাশ করে সংরক্ষিত হয় (কখনো প্লেইন টেক্সটে নয়)
- JWT টোকেন-ভিত্তিক সেশন (৭ দিন মেয়াদ, কনফিগারযোগ্য)

### প্রোফাইল

## ৬. ডাটাবেস মডেল / স্কিমা

| মডেল | বিবরণ | গুরুত্বপূর্ণ ফিল্ড |
|---|---|---|
| **User** | একজন ব্যবহারকারীর মূল তথ্য | `name`, `phone` (ইউনিক), `email`, `password` (হ্যাশড), `role` (`member`/`admin`), `address`, `avatar`, `isActive` |
| **Wallet** | প্রতিটি ইউজারের একটি ওয়ালেট (১:১ সম্পর্ক) | `user` (ref), `accountId` (ইউনিক, টাকা পাঠাতে ব্যবহৃত), `balanceBDT`, `balanceUSD`, `rewardPoints`, `savings` |
| **Transaction** | প্রতিটি ওয়ালেট কার্যক্রমের লগ | `user` (ref), `type` (send_money/payment/donation/exchange ইত্যাদি), `amount`, `currency`, `status` |
| **PaymentMethod** | ব্যবহারকারীর সংরক্ষিত পেমেন্ট পদ্ধতি | `user` (ref), `type` (bank/bkash/nagad/rocket), সংশ্লিষ্ট অ্যাকাউন্ট তথ্য |
| **Item** | এক্সচেঞ্জ প্রোগ্রামের আইটেম | `nameBn`, `nameEn`, `unit` (kg/piece), `ratePerUnitBDT`, `stock`, `active` |
| **TeamMember** | ম্যানেজমেন্ট/ফাউন্ডার টিম সদস্য | `name`, `category` (founder/co-founder/advisor/team/volunteer), `designationBn`, `bio`, `photo`, `order` |

সম্পর্ক: একজন `User`-এর ঠিক একটি `Wallet` থাকে। একটি `User` একাধিক `Transaction` ও `PaymentMethod` রাখতে পারে। `Item` ও `TeamMember` কোনো নির্দিষ্ট ইউজারের সাথে যুক্ত নয় — এগুলো গ্লোবাল/পাবলিক ডেটা।

## ৮. পদ্ধতি ১ — Docker দিয়ে চালানো (প্রস্তাবিত)

এতে frontend, backend ও MongoDB — তিনটাই একসাথে কন্টেইনারে চলবে। আলাদা করে Node/MongoDB ইনস্টল করার দরকার নেই।

তিনটি ভিন্ন Docker Compose ফাইল আছে, প্রয়োজন অনুযায়ী একটি বেছে নিন:

| ফাইল | কখন ব্যবহার করবেন |
|---|---|
| `docker-compose.yml` | **ডিফল্ট।** সাধারণ টেস্টিং/ডেভেলপমেন্টের জন্য। স্ট্যান্ডঅ্যালোন MongoDB — দ্রুত চালু হয়, সবচেয়ে নির্ভরযোগ্য। |
| `docker-compose.replica.yml` | আপনি যদি নিশ্চিত করতে চান ওয়ালেট-টু-ওয়ালেট টাকা পাঠানো সম্পূর্ণ ডাটাবেস-ট্রানজ্যাকশন-সুরক্ষিতভাবে (Atlas-এর মতো) কাজ করছে। MongoDB-কে একটি সিঙ্গেল-নোড রেপ্লিকা সেট হিসেবে চালায়। |
| `docker-compose.atlas.yml` | আপনি নিজের ক্লাউড MongoDB Atlas অ্যাকাউন্ট ব্যবহার করতে চাইলে — এতে কোনো লোকাল ডাটাবেস কন্টেইনার তৈরি হয় না। |

**বেশিরভাগ ক্ষেত্রে `docker-compose.yml` ব্যবহার করাই যথেষ্ট।** ওয়ালেট ট্রান্সফার কোড এমনভাবে লেখা যে এটি স্ট্যান্ডঅ্যালোন MongoDB-তেও সঠিকভাবে কাজ করে (শুধু সম্পূর্ণ atomic transaction-এর বদলে ধারাবাহিক আপডেট ব্যবহার করে) — তাই বাড়তি জটিলতা ছাড়াই এটি নিরাপদ।

### ধাপ ১: রিপোজিটরি প্রস্তুত করুন

```bash
cd ongikar
cp .env.example .env
```

`.env` ফাইল খুলে অন্তত `JWT_SECRET` একটি লম্বা র‍্যান্ডম স্ট্রিং দিয়ে পরিবর্তন করুন (উদাহরণ: টার্মিনালে `openssl rand -hex 32` চালিয়ে একটি র‍্যান্ডম স্ট্রিং জেনারেট করতে পারেন)। বাকি ডিফল্ট ভ্যালুগুলো লোকাল টেস্টিংয়ের জন্য ঠিক আছে।

> ⚠️ **গুরুত্বপূর্ণ:** এই `.env` ফাইলটি শুধু Docker Compose-এর জন্য। ম্যানুয়ালি (Docker ছাড়া) চালাতে চাইলে "পদ্ধতি ২" দেখুন — সেখানে ভিন্ন `.env` ফাইল ব্যবহৃত হয়।

### ধাপ ২: বিল্ড ও চালু করুন

```bash
docker compose up --build
```

প্রথমবার বিল্ড হতে কিছুটা সময় লাগবে (frontend + backend ইমেজ তৈরি হবে, এবং MongoDB ও Mongo Express ইমেজ ডাউনলোড হবে)।

চালু হয়ে গেলে যা পাবেন:

- 🌐 **অ্যাপ (Frontend):** http://localhost:8080
- 🔌 **Backend API:** http://localhost:5000/api
- 🗄️ **MongoDB:** `localhost:27017` (হোস্ট থেকে সরাসরি ইন্সপেক্ট করার জন্য এক্সপোজড)
- 🔎 **ডাটাবেস ব্রাউজার (Mongo Express):** http://localhost:8081 (ইউজারনেম/পাসওয়ার্ড ডিফল্ট: `admin` / `admin123`)

**যাচাই করুন backend আসলেই চালু হয়েছে:**

```bash
curl http://localhost:5000/api/health
# প্রত্যাশিত আউটপুট: {"status":"ok","service":"Ongikar API"}
```

সাড়া না পেলে `docker compose logs backend` চালিয়ে দেখুন — সমস্যার কারণ বাংলায় স্পষ্টভাবে লগে দেখানো থাকবে।

### ধাপ ৩: ডেটা — স্বয়ংক্রিয়ভাবেই প্রস্তুত হয়ে যায়

ব্যাকএন্ড চালু হওয়ার সাথে সাথেই স্বয়ংক্রিয়ভাবে পরীক্ষা করে দেখে ডাটাবেস খালি কিনা, এবং যদি খালি হয়:
- ৪টি ডিফল্ট এক্সচেঞ্জ আইটেম তৈরি করে (তাই নতুন ব্যবহারকারীরা সবসময় Home পেজে কিছু দেখতে পাবেন)
- একটি অ্যাডমিন অ্যাকাউন্ট তৈরি করে (নিচে দেখুন)

এই স্বয়ংক্রিয় সিডিং ব্যর্থ হলেও সার্ভার বন্ধ হয়ে যায় না — শুধু লগে একটি সতর্কবার্তা দেখাবে এবং স্বাভাবিকভাবে চলতে থাকবে। এমন হলে বা আরও ডেমো ডেটা (ডেমো সাধারণ সদস্য, নমুনা ম্যানেজমেন্ট টিম) চাইলে ম্যানুয়ালি সিড স্ক্রিপ্ট চালান:

```bash
docker compose exec backend npm run seed
```

### ধাপ ৪: ব্রাউজারে খুলুন

http://localhost:8080 এ যান। ডেমো অ্যাকাউন্ট দিয়ে লগইন করুন (নিচের টেবিল দেখুন) অথবা নিজে নতুন অ্যাকাউন্ট তৈরি করুন। অ্যাডমিন অ্যাকাউন্ট দিয়ে লগইন করলে নেভবারে **"অ্যাডমিন প্যানেল"** লিংক দেখা যাবে।

### ধাপ ৫: ডাটাবেসের ডেটা সরাসরি দেখুন

http://localhost:8081 এ Mongo Express খুলুন এবং **ongikar** ডাটাবেসে ক্লিক করুন। বিস্তারিত জন্য [সেকশন ১৪](#১৪-ডাটাবেস-সরাসরি-দেখা-mongo-express) দেখুন।

### বন্ধ করা / পুনরায় চালু করা

```bash
docker compose down              # কন্টেইনার বন্ধ, ডেটা (ভলিউম) সংরক্ষিত থাকবে
docker compose down -v           # কন্টেইনার + ডেটা সম্পূর্ণ মুছে ফেলবে
docker compose up -d             # ব্যাকগ্রাউন্ডে পুনরায় চালু
docker compose logs -f backend   # ব্যাকএন্ড লগ দেখুন (লাইভ)
docker compose logs -f frontend  # ফ্রন্টএন্ড (nginx) লগ দেখুন
docker compose restart backend   # শুধু ব্যাকএন্ড রিস্টার্ট করুন
```

### রেপ্লিকা সেট দিয়ে চালানো (ঐচ্ছিক, সম্পূর্ণ ট্রানজ্যাকশন সাপোর্টের জন্য)

```bash
docker compose -f docker-compose.replica.yml up --build
```

এটি MongoDB-কে একটি সিঙ্গেল-নোড রেপ্লিকা সেট হিসেবে চালু করে এবং স্বয়ংক্রিয়ভাবে ইনিশিয়েট করে। বাকি সবকিছু ডিফল্ট সেটআপের মতোই কাজ করে।

### MongoDB Atlas (ক্লাউড) দিয়ে চালানো

1. `.env` ফাইলে `MONGO_URI` পরিবর্তন করে আপনার Atlas connection string বসান:
   ```
   MONGO_URI=mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/ongikar
   ```
2. আলাদা কম্পোজ ফাইল দিয়ে চালান:
   ```bash
   docker compose -f docker-compose.atlas.yml up --build
   docker compose -f docker-compose.atlas.yml exec backend npm run seed   # ঐচ্ছিক
   ```

> ⚠️ ক্লাউড Atlas ব্যবহার করলে আপনার Atlas প্রজেক্টের **Network Access** সেটিংসে Docker হোস্টের আইপি (অথবা টেস্টিংয়ের জন্য সাময়িকভাবে `0.0.0.0/0`) allowlist করতে ভুলবেন না। ডেটা দেখতে Mongo Express-এর দরকার নেই — Atlas-এর নিজস্ব ওয়েবসাইটে "Browse Collections" ফিচার ব্যবহার করুন।

### Docker সম্পর্কিত গুরুত্বপূর্ণ নোট

- Nginx (frontend কন্টেইনার) `/api/*` রিকোয়েস্ট backend কন্টেইনারে রিভার্স-প্রক্সি করে, তাই ব্রাউজারকে backend-এর হোস্ট/পোর্ট জানার দরকার নেই এবং CORS সমস্যা হয় না।
- `VITE_API_URL` বিল্ড-টাইমে বেক হয়ে যায় (Vite-এর নিয়ম অনুযায়ী) — তাই এটি পরিবর্তন করলে ইমেজ পুনরায় বিল্ড করতে হবে (`docker compose build frontend`)।
- Mongo Express (http://localhost:8081) শুধু লোকাল ডেভেলপমেন্ট/টেস্টিং-এর জন্য — প্রোডাকশনে কখনো পাবলিকলি এক্সপোজ করবেন না।
- প্রোডাকশনে অবশ্যই `.env`-এ শক্তিশালী `JWT_SECRET`, `ADMIN_PASSWORD`, `ME_BASICAUTH_PASSWORD` ব্যবহার করুন এবং `.env` ফাইলটি কখনো git-এ কমিট করবেন না (ইতিমধ্যে `.gitignore`-এ আছে)।

| GET 🛡️ | `/admin/transactions` | সব ব্যবহারকারীর সব লেনদেন |
| GET 🛡️ | `/admin/items` | সব এক্সচেঞ্জ আইটেম (নিষ্ক্রিয়সহ) |
| POST/PUT/DELETE 🛡️ | `/admin/items` | এক্সচেঞ্জ আইটেম CRUD |
| GET 🛡️ | `/admin/management` | সব ম্যানেজমেন্ট সদস্য (নিষ্ক্রিয়সহ) |
| POST/PUT/DELETE 🛡️ | `/admin/management` | ম্যানেজমেন্ট টিম CRUD |

## ১৩. অ্যাডমিন প্যানেল গাইড

1. অ্যাডমিন অ্যাকাউন্ট দিয়ে লগইন করুন (উপরে "ডিফল্ট/ডেমো অ্যাকাউন্ট" দেখুন)
2. নেভবারে **"অ্যাডমিন প্যানেল"** লিংকে ক্লিক করুন, অথবা সরাসরি `/admin` এ যান
3. পাঁচটি ট্যাব পাবেন:
   - **ড্যাশবোর্ড:** সামগ্রিক পরিসংখ্যান
   - **ব্যবহারকারী:** সব ব্যবহারকারী দেখুন, খুঁজুন, তাদের ওয়ালেট সমন্বয় করুন, ভূমিকা পরিবর্তন করুন, সক্রিয়/নিষ্ক্রিয় করুন, মুছুন
   - **লেনদেন:** পুরো প্ল্যাটফর্মের সব লেনদেনের তালিকা
   - **এক্সচেঞ্জ আইটেম:** নতুন আইটেম যোগ করুন বা বিদ্যমান আইটেমের দাম/স্টক পরিবর্তন করুন
   - **ম্যানেজমেন্ট:** ফাউন্ডার/টিম সদস্য যোগ/সম্পাদনা করুন — এখানে যা যোগ করবেন তা সাথে সাথে পাবলিক `/management` পেজে দেখা যাবে

> `/admin` এ গেলে `/home`-এ ফেরত পাঠালে বুঝবেন লগইন করা অ্যাকাউন্টের ভূমিকা `admin` নয় — অ্যাডমিন অ্যাকাউন্ট দিয়ে লগইন করুন।

## ১৪. ডাটাবেস সরাসরি দেখা (Mongo Express)

অ্যাপের UI-এর বাইরে গিয়ে সরাসরি ডাটাবেসে কী আছে তা দেখতে চাইলে (শুধু Docker ব্যবহার করলে উপলব্ধ):

1. http://localhost:8081 এ যান
2. লগইন করুন — ইউজারনেম: `admin`, পাসওয়ার্ড: `admin123` (অথবা আপনার `.env`-এ যা সেট করেছেন)
3. বাম পাশে **ongikar** ডাটাবেসে ক্লিক করুন
4. কালেকশনগুলো দেখতে পাবেন: `users`, `wallets`, `transactions`, `paymentmethods`, `items`, `teammembers`
5. যেকোনো কালেকশনে ক্লিক করে ডকুমেন্ট দেখুন, ফিল্টার করুন, অথবা এডিট/মুছে ফেলুন

> এটি ঠিক MongoDB Atlas-এর "Browse Collections" ফিচারের মতোই কাজ করে, কিন্তু সম্পূর্ণ লোকাল — কোনো ক্লাউড অ্যাকাউন্ট লাগে না। ম্যানুয়াল (Docker ছাড়া) মোডে এটি থাকে না — তার বদলে MongoDB Compass বা `mongosh` ব্যবহার করুন।

## ১৬. সমস্যা সমাধান (Troubleshooting)

| সমস্যা | সমাধান |
|---|---|
| Home পেজে কোনো আইটেম দেখাচ্ছে না | প্রথমে `curl http://localhost:5000/api/health` চালিয়ে backend সাড়া দিচ্ছে কিনা দেখুন। সাড়া না দিলে এটি backend/DB সংযোগ সমস্যা — `docker compose logs backend` দেখুন। backend সাড়া দিলে কিন্তু আইটেম নেই, `docker compose exec backend npm run seed` চালান। Home পেজ এখন সংযোগ ব্যর্থ হলে স্পষ্ট লাল এরর ব্যানার দেখায় |
| `/admin` এ গেলে `/home`-এ ফেরত পাঠাচ্ছে | লগইন করা অ্যাকাউন্টের `role` `admin` নয় — অ্যাডমিন অ্যাকাউন্ট (ডিফল্ট `+8801900000000` / `admin12345`) দিয়ে লগইন করুন |
| `.env` কোনটা কোথায় কপি করব বুঝছি না | Docker ব্যবহার করলে **শুধু রুট ফোল্ডারের** `.env.example` কপি করুন। ম্যানুয়ালি চালালে `backend/.env.example` ও `frontend/.env.example` — দুটোই আলাদাভাবে কপি করুন |
| `MongoDB connection refused` (ম্যানুয়াল মোডে) | MongoDB চলছে কিনা যাচাই করুন, অথবা Atlas connection string সঠিক কিনা দেখুন |
| Docker-এ `mongo` কন্টেইনার আনহেলদি | `docker compose logs mongo` দিয়ে লগ দেখুন; পোর্ট 27017 অন্য কিছু ব্যবহার করছে কিনা চেক করুন |
| Frontend থেকে API কল ব্যর্থ (CORS) | ম্যানুয়াল মোডে backend-এর `.env`-এ `CLIENT_URL` frontend-এর ঠিকানার সাথে মিলছে কিনা দেখুন |
| Docker বিল্ডে পুরনো কোড দেখাচ্ছে | `docker compose up --build` ব্যবহার করুন (ক্যাশ এড়াতে `docker compose build --no-cache`) |
| পোর্ট already in use | `.env`-এ `BACKEND_PORT` / `FRONTEND_PORT` / `MONGO_EXPRESS_PORT` পরিবর্তন করুন (Docker) অথবা `PORT` (ম্যানুয়াল ব্যাকএন্ড) |
| Mongo Express-এ ডাটাবেস/কালেকশন দেখাচ্ছে না | ডাটাবেসে এখনো কোনো ডেটা লেখা হয়নি — সিড চালান বা অ্যাপে অ্যাকাউন্ট তৈরি করুন, তারপর পেজ রিফ্রেশ করুন |
| "৪০১ Unauthorized" এরর সব রিকোয়েস্টে | লগইন টোকেনের মেয়াদ শেষ হয়ে গেছে — লগ আউট করে আবার লগইন করুন |

## ১৭. নিরাপত্তা বিষয়ক নোট

এই প্রজেক্টটি শেখা ও ডেমোর জন্য তৈরি। প্রকৃত প্রোডাকশনে ব্যবহারের আগে অন্তত এগুলো করুন:

- `JWT_SECRET`, `ADMIN_PASSWORD`, `ME_BASICAUTH_PASSWORD` — সবকিছু শক্তিশালী, র‍্যান্ডম মান দিয়ে পরিবর্তন করুন
- Mongo Express কখনো ইন্টারনেটে পাবলিকলি এক্সপোজ করবেন না
- HTTPS ব্যবহার করুন (এই সেটআপে Nginx-এ SSL কনফিগার করা নেই)
- MongoDB-তে প্রপার অথেন্টিকেশন চালু করুন (এই ডিফল্ট সেটআপে লোকাল টেস্টিং সহজ করতে auth বন্ধ রাখা হয়েছে)
- `.env` ফাইল কখনো ভার্সন কন্ট্রোলে (git) কমিট করবেন না

## ১৮. পরিচিত সীমাবদ্ধতা / পরবর্তী ধাপ

- Google Sign-In বাটনগুলো বর্তমানে UI-only (OAuth ইন্টিগ্রেশন যোগ করা যেতে পারে)
- "টাকা চান" (Request Money) ফিচারটি এখনো একটি হালকা IOU-স্টাইল স্টাব — অনুরোধ তৈরি হয় কিন্তু counterparty অনুমোদন না করা পর্যন্ত টাকা সরাসরি স্থানান্তরিত হয় না
- ফাইল আপলোড (avatar, ম্যানেজমেন্ট টিমের ছবি) বেস৬৪ হিসেবে MongoDB-তে সংরক্ষিত হয় — বড় স্কেলে S3/Cloudinary ব্যবহার করা ভালো
- অ্যাডমিন প্যানেলে এখনো কোনো অ্যাক্টিভিটি লগ/অডিট ভিউ নেই (ওয়ালেট সমন্বয়ের জন্য শুধু ট্রানজ্যাকশন রেকর্ড তৈরি হয়)
- ইমেইল/SMS নোটিফিকেশন প্রকৃতপক্ষে পাঠানো হয় না (শুধু সেটিং হিসেবে সংরক্ষিত হয়)
